1. 파서 서버 구성
 GenAI KL에서 호출할 수 있는 API를 다음과 같이 제공해주셔야 합니다.
 1) 최초 호출 URL
    . form data : src_file (원본 문서), option (json string)
    . http method : POST
    . GenAI KL에서의 호출 예 (이해를 돕기 위해 curl로 표현)
       curl -v -X POST 127.0.0.1:8000/parsing \
         -F "src_file=@/project/work/flow/dummy.txt"  \
         -F "option=e30="
    . 정상 response status : 202
    . response body 예)
      {"result":"OK","body":{"uuid":"12378ba806e44279afdf81e6437210a9","timeout":600}}
      uuid는 변환 결과를 요청하기 위한 키이며, timeout은 결과 생성까지 KL에서 대기할 timeout을 의미합니다.
      timeout은 생략 가능하며 기본값은 3시간입니다.
      status code가 202이면서 result 값이 "OK"인 경우에 결과 요청 URL을 polling 합니다.
    . 오류인 경우 status code 500, response body에 오류 메세지를 전달합니다.
    . 30초 미만의 짧은 시간 내에 처리 가능한 경우 response status 200, 아래 2)의 zip 형태로 바로 변환 결과를 보내셔도 됩니다.
 2) 결과 요청 URL
    . 최초 호출 URL에 /result/{uuid}를 더한 값입니다.
    . http method : GET
    . GenAI KL에서의 호출 예 (이해를 돕기 위해 curl로 표현)
       curl -v -X GET 127.0.0.1:8000/parsing/result/12378ba806e44279afdf81e6437210a9 \
         -o /project/work/output.zip
    . 파싱이 진행중이면 status 200, response body {"status":"PARSING"}를 반환합니다.
    . 파싱 오류가 발생하면 status 200, {"status":"ERROR", "message": "오류 상세 내용"}를 반환합니다.
      그 외 오류가 발생하면 status 500, {"message": "오류 상세 내용"}를 반환합니다.
    . 파싱이 완료되면 status 200, zip 파일을 반환합니다.
      zip 파일 내에는 파서 변환 결과인 "원본 문서명_hrc.jsonl" 파일이 들어있어야 합니다.
 제공된 app_custom_parser 디렉토리 하위가 이를 구현한 예제이며,
 app_custom_parser/service/parsing_service.py 의 parse 함수에 프로젝트 파싱 로직을 구현해야 합니다.


2. 파서 변환 결과 양식
  파서 변환 결과인 "원본 문서명_hrc.jsonl"의 양식은 포탈의 가이드를 참고하시기 바랍니다.
  가이드 경로는 아래와 같습니다.

  portal 접속 > 좌측 하단의 GenAIs > GenAI Knowledge Lake 선택 >
   왼쪽 메뉴에서 "관리자서비스" 선택 > 상단 메뉴에서 "KL Admin" 선택 >
   "Parser 관리" 선택 > 등록 버튼 클릭 >
   Parser 유형: Custom 파서, 프로그램 유형: 소스코드제공, Custom 유형: Parsing + 구조화 선택 >
   하단 프로그램 등록의 느낌표 클릭 >
   매뉴얼 화면 팝업 > Output jsonl 단락
